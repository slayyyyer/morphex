Latency by path

Arithmetic mean latency (avgt), lower is better. Rows marked “targeted rerun” come from the post-release optimization runs and use their own same-run evo2 reference; the remaining rows are from the full workload run.

Latency relative to evo-inflector 2.0

Each bar is morphex ÷ evo2 for the same path and run. The dashed marker is parity (1.00×): bars to its left are faster, bars to its right are slower.

Measured claim: repeated lookup is 1.36× faster (81.4 vs 110.9 ns) and exact lexical hits are 1.18× faster (100.7 vs 118.5 ns). The optimized unknown and compound paths are 1.49× and 1.13× faster than the release baseline, but remain 7.57× and 4.62× slower than evo2; compacted is 1.3× slower after flattening the rule dispatch, and uppercase and unsupported remain up to 7.9× slower. The optimized rows are separate targeted reruns. No general speedup is claimed.

Node.js · V8 · not JMH

TypeScript port on Node.js

A separate runtime, harness and workload from everything above. These numbers come from morphex-ts/scripts/bench.ts on an Intel Core i5-12500H with Node.js 24.20.0: one warm-up pass, seven timed samples, median reported, first sample dropped. Five runs are shown as ranges. They are not comparable to the JMH results above and are not a cross-language speed claim.

Workload Delta engine Full engine Rules-only
Repeated lexical word (child) 111–119 ns 269–280 ns 130–139 ns
Repeated rule word (cat) 112–118 ns 174–188 ns 104–116 ns
Repeated compound (mother-in-law) 258–289 ns 434–457 ns 358–378 ns
Distinct fixture lemmas (4,000 words) 354–432 ns 1,006–1,057 ns 327–355 ns
analyze() repeated (die) 258–278 ns 421–441 ns 221–228 ns

The delta engine parses its four artifact sections and inserts them directly into an open-addressed hash index over the 124,883 keys at load time, so a rule-only word such as cat costs one hash and a short probe before the rules run. The original four-section code measured 673–678 ns; a merged binary search measured 286–293 ns; the hash index measures 112–118 ns (about 5.7–6.0× faster than the original). The index costs 1 MiB of memory; provider construction measures 50–51 ms end to end (32–33 ms parsing, 17–19 ms building the index), down from 77–81 ms before the construction changes. It is built lazily on first use. The full engine is now slower on these paths (174–188 ns) but carries complete diagnostics, and rules-only ships no data at all.

Reproduce

./mvnw -q -pl inflector-benchmarks -am package
java -jar inflector-benchmarks/target/benchmarks.jar \
  -f 2 -wi 3 -i 5 -w 500ms -r 500ms -prof gc \
  -rf json -rff results/release-1.2.0/benchmarks/jmh-workload-v1.json

The workload covers lexical hits, compacted regular words, unknown inputs, uppercase inference, compounds and unsupported inputs. Historical corpus-only runs are preserved but are not comparable to this fixed-category workload.
