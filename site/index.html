english-inflector · Java 17+

Pluralize English nouns. Deterministically.

A Java library in the spirit of evo-inflector: predictable runtime behaviour, no dependencies, no network calls, no model downloads. A 147,338-entry auditable lexicon, three productive rules, and a diagnostic API that says why a form was chosen.

Install

The 1.3.0 artifacts are built from this release. Coordinates: io.github.slayyyyer.morphex:english-inflector-core:1.3.0.


  
Rules-only runtime mode: EnglishInflector.builder().withoutBundledLexicon().build() disables loading the packaged lexicon and uses three productive rules plus your overrides. The lexical resources still ship inside the JAR, so the CC BY-SA 3.0 data attribution and distribution terms still apply.

  
New in 1.3.0: independent AGID unseen-lemma evidence, ASCII shape fast paths, and a flattened ordered rule dispatch that brings compacted lookup to 79.4 ns/op. The public API and rule precedence are unchanged. The 1.2.0 compound/casing work remains the foundation; the linear selector is still not shipped.


  
Quickstart


EnglishInflector inflector = EnglishInflector.standard();

inflector.pluralize("child");          // "children"
inflector.pluralize("CHILD");          // "CHILDREN"
inflector.pluralize("UFO");            // "UFOs"
inflector.pluralize("mother-in-law");  // "mothers-in-law"
inflector.pluralize("cat", 1);         // "cat" (source instance kept)
inflector.pluralize("cat", 3);         // "cats"

Inflection r = inflector.analyze("die");
r.plural();          // "dice"
r.alternatives();    // ["dies"]
r.ambiguous();       // true
r.source();          // LEXICON — "lex:die"






  
How does it compare?

  
evo-inflector is a compact, well-loved library; this project grew out of wanting a few more edge cases covered. Two design choices explain the differences: lookup normalization is kept separate from output case restoration, and lexical exceptions are whole-word edits rather than suffix rules, so carp can’t affect scarp and louse can’t affect blouse. That trades a larger data file for fewer surprises. evo-inflector’s smaller, simpler approach may suit you better if you don’t need the extra coverage.

JMH 1.37 on JDK 21, 2 forks, GC profiler.

  

    
100%P1 frozen-lexicon accuracy (0/36,241 errors) vs 96.474% stock

    
97.365%P2 family-holdout accuracy (955/36,241 errors) vs 96.474% stock

    
81 nsrepeated lookup vs 111 ns stock (1.36× faster)

    
1.3×slower on compacted regular words (79 vs 60 ns, flattened dispatch)

  

  
Packed lexicon retains ~18.2 MiB. External UD English EWT selected-output check: 98.76% overall (evo2 98.12%), 98.88% on the 2,148 full-vocabulary-seen lemmas, 96.69% on 363 compact-artifact hits, and 91.67% on only 36 genuinely unseen lemmas; alternative coverage 98.99%. A larger independent AGID 2016.01.19 stress test has 261 genuinely unseen lemmas: the lexicon and rules-only tie at 95.40% (249/261), evo2 95.02%. AGID is automatically generated and not a corpus; its 93.84% lexicon overall reflects 1,722 MASS/invariant identity returns against generated plurals, not a natural-text regression.
