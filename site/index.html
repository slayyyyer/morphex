Pluralize English nouns. Deterministically.

A Java 17+ library that is more correct than evo-inflector 2.0 without giving up predictable runtime behaviour. No dependencies, no network calls, no model downloads — a 157k-entry auditable lexicon, three productive rules, and a diagnostic API that says why a form was chosen.

./mvnw install   # JDK 17+; wrapper pins Maven 3.9.9
Rules-only build (no bundled Wiktionary data, no CC BY-SA obligation): EnglishInflector.builder().withoutBundledLexicon().build() — three productive rules plus your overrides. It loses irregular forms by design.

Quickstart

EnglishInflector inflector = EnglishInflector.standard();

inflector.pluralize("child");          // "children"
inflector.pluralize("CHILD");          // "CHILDREN"
inflector.pluralize("UFO");            // "UFOs"
inflector.pluralize("mother-in-law");  // "mothers-in-law"
inflector.pluralize("cat", 1);         // "cat" (source instance kept)
inflector.pluralize("cat", 3);         // "cats"

Inflection r = inflector.analyze("die");
r.plural();          // "dice"
r.alternatives();    // ["dies"]
r.ambiguous();       // true
r.source();          // LEXICON — "lex:die"

How it works

  1. Caller override — exact, case-sensitive whole-input match wins.
  2. Exact lexical entry — 157k-entry TSV, case-insensitive lookup with case-sensitive entries where needed.
  3. Supported compound — bounded table (exact entries, free tails, curated postposed heads). Unmatched input is left alone, not guessed.
  4. Productive spelling rule — only three: +es after sibilants, consonant-y → ies, default +s.
  5. Documented fallback — unsupported shapes returned unchanged and identified by analyze.
